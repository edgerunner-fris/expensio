# ADR-0012：报表仪表盘、CSV 导出与 Redis 缓存

- 状态：已接受（M16）
- 日期：2026-10-28

## 背景

报表服务目前只有一个按类别/状态聚合的 summary 接口。管理台首页需要一眼看到
本月花费、待审批量、每日趋势与预算告警；财务需要把明细导出成 CSV；
summary 每次都在事实表上现算，重复刷新会重复扫描。M16 在不引入新事实来源
的前提下补齐这三块。

## 决策

### 1. 仪表盘仍从读模型现算

`GET /api/v1/reports/dashboard?from&to&scope` 在一次事务里执行四条聚合：

- 币种总计（行数 + 金额）；
- 状态 × 币种；
- 类别 × 币种；
- 日期 × 币种（按 `occurred_at` 的 UTC 自然日）。

四条查询看到的是同一个数据库快照，因此卡片、状态图与趋势图不会互相矛盾。
不建预聚合表：租户数据量与账单同阶，现算的延迟已经可接受；预聚合要额外回答
"什么时候刷新、刷新失败怎么办"。

可见范围复用 summary 的 `resolveScope`：管理岗默认全租户，成员默认只看自己，
非管理岗显式传 `all` 返回 403 而不是静默降级。

`draft` 不会出现在读模型里——事实行只由已提交之后的事件写入，这是既有契约。

### 2. CSV 导出走同一个过滤器

`GET /api/v1/reports/expenses.csv` 接受与 summary 相同的 `from/to/scope/
status/category`，返回事实表明细。实现要点：

- 列由代码固定，不接收用户提供的列名；
- 金额同时输出主单位字符串（`money.Format`）与 `amount_minor`，避免财务
  在 Excel 里把分当成元；
- 文本列只有受约束的枚举、UUID 与时间，没有自由文本，因此不存在 CSV
  公式注入的入口；仍在写行时统一加 UTF-8 BOM，保证 Excel 正确识别中文表头；
- 上限 50,000 行，超过则要求缩小时间范围——不提供"悄悄截断"的行为；
- 文件名固定为 `expenses-<from>-<to>.csv`，不反射用户输入。

导出不做分页：它是"把当前筛选结果拿走"，不是浏览。

### 3. Redis 缓存用租户版本号失效

仪表盘响应缓存 5 分钟，键为
`report:dashboard:v<version>:<tenant>:<view>:<from>:<to>`，其中 `<version>`
是 Redis 里按租户自增的整数（`report:version:<tenant>`），`<view>` 在
`scope=all` 时是 `all`，在 `scope=mine` 时是 `mine:<user_id>`。

`<view>` 必须带用户 ID：`scope=mine` 的结果只属于提交人本人，若同租户的两个
成员用同一时间范围查询就共用键，后者会读到前者的单据。这条隔离由
`TestDashboardCacheSeparatesMembers` 回归（临时把键退回不带用户 ID 时该用例失败）。

- 报表消费者每成功处理一条事件（包括重复投递）就把该租户版本号 `INCR`；
  版本号变化后旧键自然不会再被读到，TTL 只负责清理；
- 缓存读、写、版本号读取的失败都只记 WARN 并回退到现算。Redis 不是报表的
  正确性依赖；
- summary 与 CSV **不缓存**：现有浏览器 E2E 在提交后轮询 summary，缓存会让
  "提交后立即可查"的断言变成对 TTL 的赌博。

版本号是租户级的，不做按查询参数的精确失效：仪表盘查询维度有限，多失效
几次的代价远小于维护一套参数指纹。

### 4. 预算告警在前端由整数计算

预算接口已经返回 `amount_minor/reserved_minor/spent_minor/available_minor`，
告警不需要新字段或新事件：

- 已用（预占 + 支出）达到额度 90% → 黄色"接近上限"；
- 已用 ≥ 额度 → 红色"已超限"；
- 两者都只在仪表盘与预算页展示，不改变提交时的额度校验（那条条件 UPDATE
  仍是唯一防线）。

没有做"跨服务发通知"：通知消费者目前只消费费用/账单事件，为一条预算告警
引入新的跨服务事件、DLQ 契约与收件人规则，成本高于它解决的问题。

## 备选方案

- **预聚合表**：需要额外的刷新任务与一致性解释，当前规模不值。
- **缓存 summary**：会破坏现有 E2E 的即时性断言，收益仅是少扫一次索引。
- **按查询参数精确失效**：键空间组合多，Redis `SCAN` 删除成本不可控；
  版本号是 O(1) 且不会误删。
- **导出用异步任务 + 对象存储**：50k 行以内同步流式足够，异步会引入任务表、
  轮询接口与文件生命周期三套新东西。

## 风险

- 仪表盘四条查询在大租户上可能达到几十毫秒；缓存命中后不再扫表，未命中
  时仍可接受。未做压测前不宣称"高并发可用"。
- 缓存版本号依赖消费者成功写 Redis；写失败只会让旧结果最多多存活 5 分钟。
- `scope=mine` 的缓存是按成员分割的，租户内成员越多、命中率越低；这是隔离的
  代价，不做"共享一个人视图"这类越权优化。
- 缺少 `EXPENSIO_REDIS_ADDR` 被视为配置错误，report 启动即失败（与其他依赖
  一致）；地址不可达则只是启动日志 WARN、接口回退现算，不影响 readiness。
- CSV 的 50,000 行上限是内存与响应时间的折中；超过时返回 400，由调用方
  缩小范围。
